# William's additions 4/14/2026

This document summarizes the William-owned UI/core-flow changes added today, why they were added, and any need to know new info.

## What Changed

### Single Ingredient Measure Display

- Single ingredient additions now keep their original recipe measurement.
- Unit conversion only happens once another amount for the same ingredient is added.
- Example: `8 oz` stays `8 oz` until another chicken amount, such as `500g`, is added.

Why: users should see the recipe's original wording when there is only one source. Conversion is most useful when the app is combining amounts from multiple recipe additions.

### Cart Quantity And Measure Editing

- Cart rows are read-only by default.
- Each row has an `Edit` button.
- Pressing `Edit` opens quantity and measure fields.
- While editing, `Cancel` discards draft changes and `Done` applies them.
- Quantity is rounded and kept at a minimum of `1`.
- Blank measures fall back to `To taste`.

Why: users need to adjust shopping amounts after adding recipes. This keeps the cart flexible without making every row look like a form all the time.

### Shopping Preferences

- Added a persisted Zustand preferences store.
- The cart page now includes:
  - `Lowest cost`
  - `Fewest stops`
  - optional trip budget
- Preferences are stored locally under `itemize-preferences`.

Why: the proposal includes cost/convenience tradeoffs and budget tuning. This adds the UI state needed for future store ranking without requiring backend persistence yet.

### Ready To Price / Needs Review Grouping

- Cart ingredients are now split into two sections:
  - Ready to price
  - Needs review
- Each section has its own count badge.
- Empty states are included for both sections.

Why: mapped and unmapped ingredients should not be mixed together once the cart grows. This makes the pricing readiness of the cart easier to understand.

### Store Comparison Panel

- The cart page now loads the existing mock stores from `/api/stores`.
- A store comparison section shows each store with:
  - ready item count
  - missing/unmatched item count
  - current optimization preference
  - estimated total placeholder
- Totals currently show as awaiting seeded prices.

Why: this creates the UI landing spot for seeded pricing work without inventing final pricing logic.

### Routing And Distance Placeholder

- Added a routing section on the cart page.
- Users can choose a route target store.
- The section reserves space for:
  - distance
  - drive time
  - route status
- These values are currently marked as pending Maps integration.

Why: this creates the UI landing spot for Google Maps/routing work without pretending Maps is already implemented.
